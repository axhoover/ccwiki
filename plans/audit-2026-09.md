# Audit, September 2026: what to fix before people download this

A read-through of the whole codebase with one question in mind: *what happens
when someone who is not a developer downloads CCwiki and double-clicks it?*
Every item below was verified against the code as it stands at `d62b2b7`; the
`file:line` references are to that commit. Nothing here was run, because the
review machine had no Swift toolchain. Treat the line numbers as pointers, not
as proof.

The companion document is [distribution.md](distribution.md), which covers
packaging, signing, and updates. This one is about the app itself.

Severity is judged against the *download-and-run* audience, not against the
developer who has been using it so far. That reorders some things: a bug a
developer works around in ten seconds ("relaunch it") is a bug a stranger
uninstalls over.

---

## 0. The ones that break the first launch

These are ordered by how early in a stranger's first session they bite.

### 0.1 Reading requires a working `git`, and a fresh Mac does not have one

`ToolLocator.Tool.requiredForReading` (`Sources/CCwiki/Jobs/ToolLocator.swift:27`)
is `git` alone, and `AppModel.sync` (`AppModel.swift:308-313`) refuses to run
without it. On a Mac without the Xcode Command Line Tools, `/usr/bin/git`
exists but is Apple's `xcode-select` stub: `isExecutableFile` returns true
(`ToolLocator.swift:88-90`), so `missingForReading` is empty and no warning is
raised. Running it pops the OS "install developer tools" dialog and exits 1.
The user then sees "git clone failed (exit 1). See the sync log."
(`GitService.swift:80`), and the sync log is not shown anywhere (§0.5).

Two fixes, in order:

1. **Detect the stub** (small, do now). Run `git --version` once at launch,
   off the main thread; if it fails, or stderr mentions `xcode-select`, show a
   designed state: "CCwiki needs Apple's Command Line Tools to fetch the wiki",
   with a button that runs `xcode-select --install` (which opens the system
   installer). This converts a git-flavoured error into a one-click step.
2. **Stop needing git to read** (the real fix, medium). The reader only
   *reads* the clone. GitHub serves a tarball of `main` at
   `https://codeload.github.com/axhoover/cryptology.city/tar.gz/refs/heads/main`,
   and `/usr/bin/tar` is part of the base OS, not the Command Line Tools.
   Download, extract into a temp directory, swap into place, record the
   commit from the `ETag`/API. Jobs still need real git and can keep using
   the clone when it exists. The one casualty is `GitService.modifiedDates`
   (`GitService.swift:174-194`), which walks `git log`; the folder listing
   dates would come from the GitHub commits API or be dropped when git is
   absent.

### 0.2 First launch renders every page with broken LaTeX macros, silently

`AppModel.init` (`AppModel.swift:194-196`) loads `macros.ts` *before* the
clone exists on a fresh install, gets an empty table, and bakes it into a
`documentStart` user script (`Reader/WebController.swift:43-46`).
`ccwiki.js:442-449` reads it once and caches `md`. After the auto-clone,
`loadLibrary` reloads `AppModel.macros` (`AppModel.swift:248`), so the
"macros could not be loaded" page notice (`AppModel.swift:435-440`) stops
appearing and About says "122 parsed", but the web view still holds `{}`.
Every `\calA`, `\secpar`, `\adv` on every page renders as a KaTeX error until
relaunch. The same happens after any sync that changes `macros.ts`.

Fix: when the macro table changes, either recreate the user script
(`removeAllUserScripts` and re-add, then `webView.reload()`) or send the
macros in the render payload and let `ccwiki.js` rebuild `md` when they
differ. The second is cleaner: it removes the "must be known before the web
view is built" constraint the comment at `AppModel.swift:191-193` apologises
for.

### 0.3 The app freezes for up to nine seconds before the first window

`AppModel.init` runs on the main thread from `@State private var model`
(`CCwikiApp.swift:7`). It calls `tools.locateAll()`, which for every tool not
found on PATH spawns `$SHELL -l -c 'command -v …'` and busy-waits with
`usleep` up to 3 s (`ToolLocator.swift:95-120`). A non-developer has no `gh`,
`claude` or `node`, so that is three login shells, worst case nine seconds,
before the first frame. It then calls `GitHubAuth.isAuthenticated`
(`Jobs/Preflight.swift:161-186`), which runs `gh auth status` with
`waitUntilExit` and no timeout. `gh auth status` talks to the GitHub API, so a
captive portal or slow network beachballs the app at launch. Settings repeats
both synchronously on Locate and Re-check (`AppModel.swift:593-610`).

Fix: make discovery `async`, run it in the `.task` in `RootView` after the
first frame, and show "Looking for tools…" in Settings meanwhile. The reader
does not need any of it.

### 0.4 A clone interrupted midway leaves the app stuck with an accusing message

`AppPaths.cloneExists` (`AppPaths.swift:134-137`) tests only `repo/.git`,
which git creates first. Force-quit, sleep, or a dropped connection during the
35 MB clone leaves `.git` with no HEAD. The next sync skips cloning, fetches,
runs `merge --ff-only @{u}`, fails, and shows (`GitService.swift:99-103`):
"The reader's clone has diverged from origin — CCwiki never writes there, so
something else did. Resolve it by hand, or delete the clone." There is no
delete or re-clone action anywhere in the app (Settings has Reveal, Sync,
Rebuild index: `SettingsView.swift:150-200`).

Fix: clone into a sibling temp directory and rename into place on success, so
`cloneExists` is true only for a complete clone; and add a "Reset clone"
button in Settings that deletes and re-clones. Together with §0.1 the tarball
path makes this atomic for free.

### 0.5 "See the sync log" points at a log nobody can see

`AppModel.syncLog` (`AppModel.swift:130, 344-353`) is written on every sync
and read by no view. Every failure message ends in "See the sync log."
Fix: a disclosure from the status bar, or a sheet, showing the last sync's
transcript. Small.

### 0.6 Quitting does not stop a running job

There is no `NSApplicationDelegate` anywhere (grep: the only `terminate` is
`ScreenshotRunner.swift:143`). `Subprocess` kills the process group only when
its stream is cancelled (`Subprocess.swift:171-177`), and `IngestJob.task` is
never cancelled on quit. Quitting mid-job leaves `claude` and its `node`
children running in the worktree; they may push and open a PR nobody is
watching. On relaunch the worktree is reported as orphaned
(`AppModel.swift:284-291`) with a Prune button that runs
`git worktree remove --force` on a tree a live process may still be writing.

Fix: an `NSApplicationDelegateAdaptor` with `applicationShouldTerminate` that,
when `activeJobCount > 0`, asks "A job is running. Quit and cancel it?" and
cancels every `job.task` before returning `.terminateNow`.

### 0.7 Following a `[[page#heading]]` link corrupts back/forward

`SidebarView.swift:64-67` reacts to *every* change of `sidebarSelection`,
including programmatic ones, by calling `model.openPage(path)` with no anchor.
`AppModel.open` (`AppModel.swift:366-381`) sets `location = .page(path,
anchor)` and `reveal()` sets `sidebarSelection = path`, which fires the
observer, which opens `.page(path, nil)`. `Location` equality includes the
anchor (`AppModel.swift:58-61`), so the anchored entry is pushed onto `back`
and `forward` is cleared. Consequences: after a cross-page anchored link, Back
lands on the same page and must be pressed twice; and pressing Back onto any
anchored entry destroys the Forward stack. Reached by the 13 anchored links in
the corpus and by every variant opened from the Relations pane
(`openRelationObject`, `AppModel.swift:478-483`). No test covers
`goBack`/`goForward`.

Fix: the observer should compare the selected path with the current
location's path and return early when they match; or drive sidebar clicks
through an explicit action instead of observing the selection. Add a history
test: open A, follow A → B#x, Back, Forward.

### 0.8 The web view cannot recover from a reload or a WebContent crash

`WebController` (`WebController.swift:20, 67-82, 130-135`) sets `isReady`
once and never resets it; `loadedPath` is cleared only by `invalidate()`. It
implements neither `webViewWebContentProcessDidTerminate` nor any navigation
callback. WKWebView's default context menu offers Reload on blank areas, and
`decidePolicyFor` allows the shell URL (`:198-201`), so a stray right-click
blanks the reader; `render()` for the current page then short-circuits at
`:72` and the only way out is navigating elsewhere or relaunching.

Fix: implement `webViewWebContentProcessDidTerminate` and `didFinish` to
reset `isReady`/`loadedPath` and re-render the current location; replace the
default context menu (see §2.4).

## 1. Correctness, the rest

Ordered by likelihood of being seen.

- **1.1 HTTP errors are reported as "offline".** `GitService.isNetworkFailure`
  (`GitService.swift:52`) matches `"unable to access"`, which git prefixes to
  every HTTP failure: 403, 404, a proxy 407, a certificate problem. All of
  them show the muted "reading from the last pull" wifi-slash instead of an
  error. `SyncTests.swift:31` tests `Authentication failed for` without git's
  real `unable to access '…':` prefix, so the suite misses it. Drop the
  catch-all; keep the specific phrases.
- **1.2 Cancel is checked too late in the runner.** `IngestJobRunner.swift:73-92`:
  cancelling during `worktree add` overwrites the `.cancelled` state with
  `.failed("Could not create the worktree…")` (the `Task.isCancelled` check is
  at `:80`, after); cancelling during the submodule update falls through to
  composing the prompt and spawning `claude`, which is then immediately
  killed; and `AppModel.start` (`AppModel.swift:690-697`) runs
  `refreshOrphanedWorktrees()` inside the cancelled task, gets `[]`, and
  clears the orphan list. Check `Task.isCancelled` after every await and do
  the bookkeeping in a fresh `Task`.
- **1.3 `AppModel.open` never checks the page exists.** `renderCurrent`
  (`AppModel.swift:444`) silently returns for an unknown path while the
  chrome (title, selection, history) has already moved. Reachable from
  `RelationsView.swift:210, 238` (manifest paths not guarded like
  `openRelationObject` is), from stale FTS hits after a pull that deleted a
  page (the rebuild is fire-and-forget, `AppModel.swift:268-277`), and from
  `WikiIndex.build` registering a slug for a page whose load failed
  (`WikiIndex.swift:53-62`). Guard in `open`, and show the "page not found"
  state that already exists for dead links.
- **1.4 Multi-line `%% comments %%` are not masked.** `CodeMask.inlineInertRanges`
  (`Wiki/Wikilink.swift:170-187`) only pairs `%%` on one line; Quartz strips
  `/%%[\s\S]*?%%/g` across lines. Links inside a multi-line comment become
  backlinks and "N links have no target" notices the site never shows.
  Indented (four-space) code blocks are also not inert. One fixture each.
- **1.5 Push preflight tests that a helper exists, not that it works.**
  `GitService.canAuthenticatePush` (`GitService.swift:138-150`) reads
  `credential.helper` without `--local`, so a global `osxkeychain` with no
  token passes the blocking check and the push still fails at the end of a
  long job. `configureCredentialHelper` (`:121-133`) also writes `gh`'s
  absolute path once and never refreshes it. Check for real:
  `gh api repos/axhoover/cryptology.city --jq .permissions.push`.
- **1.6 Job outcome is inferred from prose.** `ClaudeStream.swift:237-241`
  treats any `ABORTED:` substring in the final message as an abort and
  `findPullRequestURL` (`:225-234`) takes the last `/pull/N` in the text; a
  message quoting the protocol or mentioning an earlier PR is misclassified.
  Confirm with `gh pr view --head <branch> --json url` after the run.
- **1.7 Job ids collide within a second.** `IngestJob.swift:90-92` builds the
  id from a local-time `yyyyMMdd-HHmmss` stamp plus the slug; two submissions
  of one paper in the same second share a worktree path.
- **1.8 Swift heading ids can diverge from the web view's.**
  `WikiPage.headings()` (`WikiPage.swift:188-190`) requires `#` at column 0
  and a space after the hashes, and keeps a closing `##` (`## Foo ##` gives
  `foo-`); markdown-it accepts three leading spaces and strips closing
  sequences. Consumers are variant labels (`RelationLabels.swift:108-116`)
  and the FTS `headings` column. Low, but the doc comment at `:169-174`
  claims they are identical and they are not.
- **1.9 Frontmatter divergences from Quartz.** `Frontmatter.list`
  (`Frontmatter.swift:46-52`) keeps a scalar as one item where Quartz's
  `coerceToArray` splits on commas (`aliases: PRF, PRP`); a quoted scalar
  followed by a comment keeps its quotes (`:213-216`); `key: [[wikilink]]`
  parses as a flow sequence (`:112`). Corpus tests pass today because the
  corpus does not contain these; add fixtures so the next page that does is
  caught.
- **1.10 `.md` is stripped anywhere in a filename**, not just as the
  extension (`WikiPage.swift:107, 156-157`). `shortTitle` (`:126`) is a dead
  conditional.
- **1.11 The search index has no schema version.** `SearchIndex.schema`
  (`SearchIndex.swift:194-238`) is all `IF NOT EXISTS`; a tokenizer or weight
  change silently keeps the old index. Add `PRAGMA user_version` and reset on
  mismatch. Needed before the ranking work in [search.md](search.md) §6.
- **1.12 Transcript lines can be dropped.** `Subprocess.swift:108` uses
  `.bufferingNewest(8192)`; if the main actor falls behind (see §3.1) the
  oldest lines vanish from the log the user is reading.

## 2. Usability, for someone who reads more than they ingest

The reader is the product for almost everyone who downloads this; ingestion
needs three developer tools and push rights to the wiki. The list below is
what a reader notices, roughly in the order they notice it.

- **2.1 Content goes stale and nothing says so.** Sync runs only when there
  is no index (`RootView.swift:49`). There is no fetch on launch and no
  periodic fetch; the status bar shows a 7-character commit hash
  (`RootView.swift:176-182`). Do: fetch quietly on launch and every few hours
  when online; show "Updated 3 days ago" with the hash in the tooltip; offer
  "Wiki updated, 4 pages changed" as a status-bar note when a pull lands.
- **2.2 No text size control.** Only pinch magnification is on
  (`WebController.swift:58`); `CCwikiCommands` has no ⌘+ / ⌘−; body size is
  fixed at 16 px (`app.css:69`); nothing persists. Standard View menu items,
  a persisted `pageZoom`, and ⌘0 moved off "Go Home" (which belongs on ⇧⌘H).
- **2.3 Nothing is remembered between launches.** Location, inspector state,
  expanded folders, history (`AppModel.swift:69-83`) are in memory only;
  cold start always goes home (`AppModel.swift:295`). Persist the last
  location and the expanded folders; add a "Recent" list to the quick
  switcher's empty state.
- **2.4 No "Open on cryptology.city", no "Copy link", no copy-TeX.** The
  Wiki menu has only Reveal in Finder (`CCwikiApp.swift:101-112`); rows in
  search, quick switcher, backlinks and relations have no context menus
  (`SearchView.swift:94-102`, `QuickSwitcherView.swift:87-95`,
  `InspectorView.swift:98-118`, `RelationsView.swift:208-260`). `page.slug`
  *is* the site path, so both are one-liners. `render-pipeline.md` §3 promises
  a native right-click menu that can copy the original TeX; nothing implements
  a `WKUIDelegate` menu. That menu would also remove the stray Reload (§0.8).
- **2.5 ⌘-click is advertised and discarded.** `ccwiki.js:546` posts
  `modified`, `WebController.swift:161` forwards it, `AppModel.swift:206-208`
  drops it. Either open in a new window (a `WindowGroup(for: String.self)`
  keyed by path) or stop sending it. A second window is genuinely useful for
  reading a definition beside a reduction.
- **2.6 Find shortcuts are shown but not bound.** `ReaderView.swift:192, 197`
  say ⌘G / ⇧⌘G in tooltips; no `keyboardShortcut` exists. `dismissFind`
  (`:214-218`) leaves WebKit's highlight in place.
- **2.7 Search snippets excerpt the wrong column and leak markup.**
  `snippet(doc_fts, 3, …)` (`SearchIndex.swift:326`) always excerpts the
  body, so a title-only hit shows the first 14 body tokens; `indexableBody`
  (`:306-316`) leaves `#`, `**`, `_` and list markers in. Use column `-1`
  and strip the rest.
- **2.8 The ingestion sheet lets you submit into a wall.** `canSubmit`
  (`IngestSheet.swift:28-30`) gates only on input validity; a user without
  `claude`, `gh`, `node` or push rights submits, the Jobs window opens, and
  the job dies with terminal instructions. Show the preflight state in the
  sheet and disable Start with a reason.
- **2.9 Jobs vanish on relaunch.** Jobs live in memory (`AppModel.swift:155`);
  transcripts in `logs/` are never read back (`JobsView.swift:115-117` only
  reveals them). A PR URL from a job that finished before a relaunch is lost.
  Persist a small record per job (id, source, state, PR URL, log path) and
  rebuild the list from it. Also missing: retry, clear finished, a
  concurrency cap.
- **2.10 Warnings accumulate and cannot be dismissed.** `warnings.append`
  on every failed sync (`AppModel.swift:333`) stacks duplicates; the
  first-launch "macros.ts missing" warning (`:214-217`) is never removed once
  the clone lands. Make warnings keyed and dismissable.
- **2.11 Settings speaks to developers.** The first tab is command-line tool
  paths; GitHub shows "Not signed in" with only Re-check
  (`SettingsView.swift:46-76`). Lead with a General tab (text size, hide
  stubs, update check, storage); move tools under "Ingestion"; give the
  GitHub row an "Open Terminal and sign in" button, which `openInTerminal`
  already makes cheap.
- **2.12 Developer signals in the page.** Unresolved wikilinks render
  red-dashed with `cursor: help` (`app.css:176-180`) and every such page gets
  a "N links on this page have no target" notice
  (`RenderRequest.swift:121-127`). Keep the styling, drop the banner for
  readers, or gate it on a "show wiki lint" preference.
- **2.13 Accessibility.** Toolbar buttons have `.help` but no
  `accessibilityLabel` (`RootView.swift:67-104`); search and quick-switcher
  rows are plain views with `.onTapGesture`, so VoiceOver sees nothing
  actionable and rows have no keyboard focus; the inspector's `Picker("")`
  with `labelsHidden` has no label (`InspectorView.swift:21-27`); folder rows
  open only on double-tap (`SidebarView.swift:174`). Use `Button` rows and
  label the controls.

## 3. Performance

None of these are visible on a fast Mac with 700 pages. They will be on a
2019 Intel laptop, and two of them scale with the corpus, which grew 380
pages in one migration.

- **3.1 Every transcript line is processed on the main actor.**
  `IngestJobRunner` is `@MainActor` (`IngestJobRunner.swift:17`); the `for
  await` body (`:148-168`) does a synchronous `FileHandle.write` per line
  (`IngestJob.swift:145-153`), a `JSONSerialization` per line, and mutates the
  observed `log` array so SwiftUI re-diffs the transcript per event;
  `log.removeFirst(1_000)` (`:136`) is O(n). Parse and write on a background
  task; batch UI appends every ~100 ms.
- **3.2 Scroll events flood the bridge.** `ccwiki.js:549-551` posts
  `scrolled` on every scroll event, each running a `getBoundingClientRect`
  loop; `WebController.swift:154-155` assigns `activeHeadingID`
  unconditionally, and `@Observable` notifies on every assignment, so the
  Outline list rebuilds per tick. Compare before assigning; coalesce with
  `requestAnimationFrame` in JS.
- **3.3 The sidebar rebuilds the tree in `body`.** `SidebarView.swift:29,
  35-41` calls `pageTree()` and two `count(ofKind:)`, each allocating
  `index.allPages` (`WikiIndex.swift:151`) and sorting with
  `localizedCaseInsensitiveCompare`, on every navigation. Cache on
  `index`/`hidesStubs`/`unlistedPaths`. (`SWIFTUI-RULES.md` §6.3.)
- **3.4 Barrier pages sweep reductions × barriers in `body`.**
  `RelationsView.swift:25` → `PageRelations.groups(for barrier:)`
  (`PageRelations.swift:171-173`) → `barriers(contradicting:)`
  (`RelationsManifest.swift:363-370`) builds two `Set`s per pair, roughly 12k
  allocations per evaluation. Precompute a barrier → reductions map at
  manifest load.
- **3.5 Eight or more git spawns per sync.** `loadLibrary`
  (`AppModel.swift:226-298`) runs a full-history `git log`,
  `configureCredentialHelper` twice (`:262-263` and via
  `refreshPushCapability` `:618-621`), `canAuthenticatePush`, `worktree
  repair`, `worktree prune`, `worktree list`, then a full FTS wipe-and-reinsert
  (`SearchIndex.swift:114-124`). Off-main, so it is latency in "Indexing…",
  not a freeze. Do the job-related ones lazily, and index incrementally from
  `git diff --name-status before..after`.
- **3.6 The scheme handler reads whole files on WebKit's thread.**
  `CCwikiSchemeHandler.swift:327` uses `Data(contentsOf:)`; a large embedded
  image blocks the UI for the read. Dispatch the read; keep `stop` correct.
- **3.7 The quick switcher re-scores the corpus per keystroke, undebounced,
  on the main actor.** `quickSwitcherQuery.didSet` (`AppModel.swift:147-149`)
  → `FuzzyMatcher.match` allocates three arrays per candidate
  (`FuzzyMatcher.swift:420-426`). Fine today; precompute the lowercased
  candidate arrays once per index.
- **3.8 Toggling "Hide stubs" or syncing re-renders the page you are reading
  and scrolls to the top** (`AppModel.swift:25-33, 294-295`;
  `ccwiki.js:489-493`). Only folder listings need the re-render.

## 4. SwiftUI rules the code breaks

Cited against `SWIFTUI-RULES.md`.

- **§1.1** `RootView.swift:44, 124-125`: `dropOverlay` is inserted with `if`
  and carries `.transition(.opacity)` inside a `NavigationSplitView`. Keep it
  mounted and animate opacity.
- **§2.3** `RootView.swift:172-174`: the `.succeeded` status text has no
  `lineLimit`, unlike its siblings, inside a fixed 26 pt bar.
- **§5.1** `RootView.swift:115`: `.font(.system(size: 48))` on the drop icon.
- **§6.3** the `body` computations in §3.3 and §3.4.
- **§7.4** no context menus on actionable rows (§2.4).
- **§4.3** `listRowSeparator(.hidden)` on the outline list but not on the
  backlinks or relations lists in the same inspector.

## 5. Verified sound, so nobody re-audits it

- FTS `MATCH` escaping (`SearchIndex.swift:363-383`): every token quoted,
  `"` doubled, NUL stripped, expression and `LIMIT` bound. No injection path.
- `Subprocess.lines` drains both pipes via readability handlers and reports
  exit after both EOFs; `stdin` is `/dev/null` so prompts fail fast.
- `QuartzSlug`, `GithubSlugger`, `splitAnchor`, `transformInternalLink` match
  the Quartz sources they cite. `RelationsManifest` degrades per field.
  `PageRelations` never emits a pair.
- Memory is bounded: history 100, sync log 400, FTS results 60, quick
  switcher 40.
- `WKNavigationDelegate` decision handlers carry the `@MainActor @Sendable`
  spelling (`WebController.swift:187-191`), so link interception works.
- Dark mode in the web view is handled; the Outline tab is a table of
  contents. Both were checked because they are common gaps; neither is one.
